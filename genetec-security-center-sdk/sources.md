## How these sources were retrieved

The portal is a **Fluid Topics** single-page application: page content is rendered inside shadow DOM and an iframe, so ordinary text extraction returns only "Skip to main content". Content was therefore retrieved through the portal's own read API:

```
GET /api/khub/maps                                   -> catalogue of 170 documentation maps
GET /api/khub/maps/{mapId}/pages?v=1                 -> table of contents (tocId, contentId, title, prettyUrl)
GET /api/khub/maps/{mapId}/topics/{contentId}/content -> topic body as HTML
```

The critical detail for anyone repeating this: the content endpoint requires the **`contentId`**, not the `tocId`. Endpoints that do *not* work on this tenant: `/internal/api/webapp/pretty-url/reader` (404, "This tenant does not have any pretty-url"), `/api/khub/search` (405 on POST, 404 on GET), `/internal/api/webapp/search` (400), `/api/khub/maps/{mapId}/toc/{tocId}/content` (404), `/api/khub/topics/{contentId}/content` (404).

Note that a document's top-level `paginatedToc` entries are often stubs; the substantive topics live in each entry's nested `pageToc` array. Walking only `children` yields 38 nodes for the Developer Guide; walking `pageToc` as well yields the full 206.

## Grounding conventions used throughout this skill

- Exact strings — file paths, service and process names, port numbers, registry keys, config keys, default values, class/method/property names, error codes and error messages — are reproduced **verbatim**. Everything else is paraphrased; no long passages are reproduced.
- Every section in every reference file carries the source ID(s) it rests on.
- `[INFERRED — verify]` marks a high-confidence statement that the documentation does not actually make.
- "Not documented" means the vendor documentation did not answer the question; those items are listed in `known-gaps.md` rather than being filled in from general knowledge.
- Instructions, calls to action and contact prompts appearing inside fetched pages were treated purely as data.
