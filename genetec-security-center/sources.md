## How these sources were retrieved

The TechDoc Hub renders content inside closed shadow DOM custom elements (`FT-*`), so page text extraction returns nothing. Content was retrieved through the platform's public REST API on the same origin:

| Endpoint | Use |
|---|---|
| `GET /api/khub/maps?limit=3000` | Enumerated the full document inventory (2,802 maps) in place of `sitemap.xml` |
| `GET /api/khub/maps/{mapId}` | Title, `readerUrl` and `lastEdition` for each source row above |
| `GET /api/khub/maps/{mapId}/toc` | Table of contents, used to select relevant topics |
| `GET /api/khub/maps/{mapId}/topics/{contentId}/content` | Topic HTML, converted to text with tables flattened to pipe-delimited rows |

`POST /api/khub/search` returned HTTP 405 and the GET form returned 404, so document discovery was done by filtering the cached map inventory with regular expressions instead. Non-English maps (French, Spanish and German editions of the same documents) were filtered out.

- The port guides are the authoritative mapping of ports to **executable names**, which is why `architecture.md` derives its process table from them.
- `S13`, `S17`, `S18`, `S19` and the standalone troubleshooting articles are living pages with no version in the title; their edition dates are the only version signal available.
- `S27` (Cybersecurity best practices) has an edition date of **2020-10-19** and was used for context only; nothing in this skill relies on it.
- One retrieved topic in `S12` contains a leaked internal work-item string in place of a procedure step. See `known-gaps.md`.
