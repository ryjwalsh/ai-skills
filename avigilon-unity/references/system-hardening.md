# Avigilon System Hardening Guide (bundle system-hardening)
Base: https://docs.avigilon.com/bundle/system-hardening/page/<path>

- Checklist: NVR — first boot auto-enables BitLocker + new admin password; create OS recovery USB; back up BitLocker keys (OS + data); disable USB ports. Cameras — strong admin password, latest firmware, CA-signed cert, FIPS 140-2. Clients — CA cert on server+clients, FIPS mode, WAN (secure) connection. [checklist.htm]
- Passwords ≥14 chars mixed. Account types: Windows/AD user, basic user, network service. AD in Unity: port 38883 UDP (Unity) / 389 UDP (ACC) open server↔DC. Enable: New Task > Site Setup > site > Users and Groups > External Directory tab > Active Directory > Edit > "Use Unity Video Server account" (service account = Log On account of the Windows service) or domain creds > OK. Note: enabling AD disables previously imported Unity Access roles. Import groups: Add Group > template > Locations… (other domain) > name/Advanced… > OK. Import users: Add User > … > Edit User > Member Of tab. Camera users: web UI Users page > Add… > Username/Password > Security Group Administrator / Operator (live+PTZ, limited setup, SD settings) / User (live, optional Use PTZ Controls) > Apply. [general-guidelines/account-management.htm]
- iDRAC default password printed on luggage tag; change: F2 at boot > iDRAC Settings > User Configuration > root > Change Password. iDRAC reset reverts to tag password. [securing-recorders/idrac-password-change.htm]
- OS recovery USB (NVR6 / FIPS): 32 GB USB, Win10 1703+; download Avigilon Recovery Image at avigilon.com/software-downloads > OS Recovery page (Product filter). diskpart: list disk > select disk x > clean > convert gpt > create partition primary size=1024 > format fs=fat32 quick > assign > create partition primary > format fs=ntfs quick > assign > exit. Unzip image; "images" folder → 31 GB NTFS; all other folders → 1 GB FAT32 (ISO: mount and copy same way). Verify images\<model>\*.wim. Errors logged to X:\nvr_recovery.log on the USB. [securing-recorders/create-usb-recovery-key.htm]
- Enable TPM: Device Manager > Security devices; else F2 > System BIOS Settings > System Security > TPM Security On > Exit/save > restart. [securing-recorders/enable-tpm-nvr.htm]
- BitLocker on Windows Server: Services > "Windows Remote Management (WS-Management)" Automatic + Start > Server Manager > Manage > Add roles and features > Features > BitLocker Drive Encryption > Install (reboot) > disable WinRM again > Admin Tool > Shut down (status Not running) > Manage BitLocker > Turn on BitLocker for C: (save key; full disk; New encryption mode) > then D: with "Automatically unlock this drive on this computer" (optional: Disk Management > format D: NTFS label Storage first) > check `manage-bde -status` = Fully encrypted > Admin Tool > Settings > Storage > select D: > Add data volume… (max) > OK > Start up. [securing-recorders/bitlocker-setup-nvr.htm]
- FIPS NVR: LAN live streaming unsupported → Clients must use WAN mode. [securing-fips-recorders/must-use-wan-mode.htm]
- USB ports (FIPS NVR): C:\Avigilon\3rdPartyInstallers\UsbPortConfigurationTool.exe as admin > [A] All On / [O] All Off / [B] Back on, front off > Y > restart. From BIOS: F2 > System BIOS Settings > Integrated Devices > User Accessible USB Ports > All Ports On / Only Back Ports On. [securing-fips-recorders/enabling-usb-ports.htm]
- iDRAC OOBM port disabled by default on FIPS NVR: F2 during POST > iDRAC Settings > Network > enable + settings > Back > Finish > Yes. [securing-fips-recorders/enabling-oobm-port.htm]
- Server CA cert (certlm.msc > Personal > Certificates > All Tasks > Request New Certificate > AD Enrollment Policy > Properties: General Friendly Name AccServerCert (or UnityServerCert); Subject tab > Alternative Name DNS = FQDN; Private Key tab > Make private key exportable (+custom permissions if service runs as specific user) > Enroll). Criteria: LocalMachine\Personal store, friendly name exact, exportable key, SAN = FQDN, no SHA1, CAs in Trusted Root/Intermediate stores on all servers+clients. Export CAs: cert > Certification Path > View Certificate > Details > Copy to File… (no private key). Import on other machines: certlm.msc > Trusted Root Certification Authorities > Certificates > All Tasks > Import. Restart "Avigilon Unity Orchestrator Service" after. Then Site Setup > site > Security > "Require trusted server certificates"; Client > ⋮ > Client Settings > Security > "Require trusted server certificates". Verify: https://<fqdn>:38881 lock icon = Certificate (Valid). Manual login must use full FQDN. [securing-network/self-signed-certificates.htm]
- Endpoint/AV exclusions: folders AvigilonData (data volumes) + AvigilonConfig (config volumes; see Admin Tool > Settings > Storage); processes under C:\Program Files\Avigilon\Avigilon Unity * (Platform Monitor Service, Analytics Service AnalyticsDaemonService.exe, API Gateway pgsql/pgbouncer/VmsApiGateway.exe, Client VmsClientApp.exe, Cloud Bridge VmsCloudBridge.exe, Orchestrator VmsOrchestratorService.exe, Server VmsDaemonService.exe/VmsAdminPanel.exe/VmsUpgraderApp.exe/LPR6\LprDaemonApp.exe, Virtual Matrix, Web Endpoint node.exe/WebEndpointService.exe, Player) and ACC equivalents (Avigilon Control Center Client/Gateway VmsWebGateway.exe/Server/Web Endpoint). FIPS servers cannot connect to Unity Cloud. [securing-network/configure-endpoint.htm]
- FIPS 140-2 mode: server — Site Setup > site > Security > FIPS 140-2 Mode Off / Relaxed (prefer FIPS, allow fallback; use during initial config, pre-7.8 components, non-FIPS integrations) / Strict. Client — ⋮ > Client Settings > Security > FIPS 140-2 Mode Off (SRP login) / Relaxed / Strict > restart client (need not match site). Avoid web links in panels, Maps, Cloud sign-in, cloud sharing/exports when FIPS required. [securing-network/configuring-fips-compliance.htm]
- Run service as network service: services.msc > Avigilon service > Properties > Log On > This account: NT AUTHORITY\NetworkService, blank password. [securing-network/network-service-account.htm]
- Firewall ports (see system-setup notes for full table; extras here): Pelco SOAP driver 59595 TCP; RTMP 1935 to Unity Cloud (3rd-party video); Web Endpoint REST 8443 (Windows) / 443 (appliance); SSDP 1900 UDP / 49152 TCP; mDNS 5353; WebRTC 49152-65535 (Windows) / 32768-60999 (appliance); SMTP 25; Unity AI 28831-28833; Cloud: 443 HTTPS/AMQP, STUN 49152-65535 UDP, TURN 443 TCP/UDP + 3478 UDP; Flexera licensing 4433; installers.avigilon.com 4434 (Software Manager). Changing base HTTP port 38880 shifts 38881/38882; changing base RTP 51000 shifts 51000-55000. Server discovery 38883 closed by default on hardened NVRs. [securing-network/use-firewalls.htm]
- Encrypt live video: Client > ⋮ > Client Settings > Security > "Encrypt video from all sites"; or Site Networking tab > site > Connection Type WAN (Secured) (up to 30% NVR throughput cost). [securing-network/video-encryption.htm]
- Camera: factory revert button hold 3 s; keep creds after revert = web UI Users page bottom > "Do not clear usernames or passwords on firmware revert" (lost password then voids warranty; not FIPS-compliant storage). Backup admin: CCT > Admin Users tab > Secondary Admin User Name/Password > Apply. [devices/keep-password-after-revert.htm]
- Camera encryption engine: Client > Site Setup > device > Network > Encryption Mode (OpenSSL default H5A — FIPS 140-3 L1 on fw 5.34.0.36+ no license; NXP TPM default H6A; FIPS 140-2 Level 1 needs CAM-FIPS license) > OK (reboot 1-5 min). CCT: TLS tab > Encryption Mode column > Apply. Web UI: Advanced Network page > Encryption Engine > Apply. [devices/camera-fips-enable.htm]
- Camera 802.1x: web UI Network > 802.1x > EAP Method PEAP (Configuration Name, EAP Identity, Password) or EAP-TLS (TLS Client Certificates PEM, Private Key, Private Key Password > Upload Files) > Save Config; only one profile enabled (select > Enable / Remove). [devices/config-802-authentication.htm]
- Change device LAN→WAN (needed if ICMP blocked): site Setup > Connect/Disconnect Devices > select > Edit… > Network Type WAN (Secure) (Avigilon, encrypted) or WAN (3rd-party/non-HDSM) > OK. [devices/changing-network-type.htm]
- Disable server auto-discovery: edit VmsDaemonConfig.cfg (server install folder) inside <Root>: <DevClient><DeviceDriverAvigilon><ConfigItem name="AvigilonDiscoveryEnable" type="Boolean" value="0"/></DeviceDriverAvigilon><DeviceDriverOnvif><ConfigItem name="OnvifDiscoveryEnable" type="Boolean" value="0"/></DeviceDriverOnvif></DevClient> > reboot server; add devices manually afterwards. [devices/disable-discovery.htm]
- Device certs: import CA/intermediate into server Local Computer store (mmc > Certificates snap-in > Computer account > Intermediate/Trusted Root > All Tasks > Import). Then Site Setup > site > Security > Device Security Settings > "Require trusted device certificates" (blocked if any device fails; run "Device certificate report" first to list non-compliant/expired). [devices/manage-device-certificates-acc.htm]
- HTTPS always on for cameras; change ports via CCT Network tab HTTP Port # / HTTPS Port # or web UI Network page. [devices/enable-https.htm]
- Workstation hardening kit AvigilonSecureWorkstation-X.X.X.X-win10.zip (Partner Community) > unzip > run AvigilonSecureWorkstation.bat as admin (~5 min) > restart; remaining STIGs manual. TLS ciphers: gpedit.msc > Computer Configuration > Administrative Templates > Network > SSL Configuration Settings > SSL Cipher Suite Order > Enabled > edit list > restart. [workstations/run-hardening-kit.htm]
