# AI NVR 2 Premium Form D User Guide (bundle ai-nvr-2-premium-form-d) — applies broadly to Avigilon hardened-OS appliances (AI NVR / AI NVR 2 / ENVR2 / ENVR2X) "Server Management" / "Management Interface" WebUI
Base: https://docs.avigilon.com/bundle/ai-nvr-2-premium-form-d/page/<path>

- First connect (DHCP): Client > Site Login list > site "AINVR2-PRM-xxTB-<serial>" > username administrator pre-filled, blank password > Log In > set new ACC admin password. Then Explorer > right-click appliance > Setup > select server > Server Management > Trust certificate > create separate OS administrator password (recommended different from ACC admin). Only "administrator" can log in to Server Management. [ainvr2/first-connect-dhcp.htm]
- First connect (static IP / first appliance): Windows File Explorer > Network (or Finder) > device "AINVR2-PRM-xxTB-<serial>" > double-click opens https://<ip>/ (self-signed cert warning: Chrome Advanced > Proceed) > set administrator password > Network panel > each pane > IP tab > toggle Automatic IP off > IP Address / Subnet Mask / Default Gateway > Apply. [ainvr2/first-connect-static-ip.htm]
- Open Server Management later: Client > New Task > Site Setup > select server > Server Management; or browser https://<ip or hostname>/ (hostname/IP shown in Client server Setup tab). Log out via icon on title bar. [ainvr2/open-server-management.htm]
- Dashboard cards: ACC Server (Running green / Stopped red, site name/server name/version), System (Ready/Rebooting/Initializing, product, part #, serial, firmware, date/time, Secure Boot), Storage, Network (uplink speed up/down), Accelerators (GPU status). [ainvr2/open-server-management.htm]
- Navigation: ACC > Server panel (services, LPR Performance Mode, Reinitialize, Network Storage Management, Service Ports / RTP Ports base values → restart); System > Device panel (General: Language, Hostname, Password, Time, Certificates, Upgrade Firmware, Support downloads: Device Logs, System Snapshot, Dell SupportAssist Collection); Network panel; Storage panel; Logs panel (Server Logs tab / System Logs tab). [ainvr2/manage-device-settings.htm]
- First-time basics: Device > General > Language; Hostname (default = <Model>-<Serial>); Time > Time Zone + NTP (DHCP / Manual list / Off; defaults 0-3.pool.ntp.org; appliance serves NTP on port 123 to ONVIF cameras; Avigilon cameras use appliance as NTP by default). [ainvr2/manage-time.htm]
- Change OS admin password: Device > General > Password pane > Old/New/Confirm. Forgotten password ⇒ factory restore only (config + video lost). [ainvr2/change-admin-password.htm]
- NIC teams: Network panel > New Team > Add Member (2+ ports) > Mode (Active Backup [Primary Member or Automatic] / Link Aggregation Control Protocol / Adaptive Load Balancing) > Apply (takes minutes; ports replaced by team pane; edit on Teaming tab; Remove Team). Note IPs first — may lose connection. Identify physical port: Network panel > Identify toggle (LEDs flash, auto-off 10 min). [ainvr2/create-nic-teams.htm]
- Certificates: Device > Certificates pane > Web Certificate tab > Certificate Signing Request > fill > Generate (generated.csr in Downloads) > Upload .crt (+ .key if CSR not from device; no passphrase certs) > click cert name to enable. User Certificate Authorities tab > Upload (internal CA for SMTP etc.). Only governs Server Management/WebEndpoint web cert + SMTP validation, NOT server-server/server-client. Factory reset removes custom cert. [ainvr2/manage-certificates.htm]
- Firmware upgrade (.fp): download from avigilon.com/video-infrastructure/ai-nvr-2 (Community login) > Device > Upgrade Firmware pane > drop .fp > OK > uploads/verifies then auto-upgrades, reboots several times ("Web UI Communication Lost"). Alternatives: Cloud Remote Site Upgrade (ACS Advanced System Health) or Client Site Update. Settings/video retained. [ainvr2/upgrade-firmware.htm]
- ACC services: Server panel > General > Stop / Start; Reinitialize (wipes config + video); LPR Performance Mode toggle (disables Classified Object Detection + Face Recognition); Download Client installer. Service Ports pane Base value (HTTP/HTTPS/UDP); RTP Ports pane Base → restart required. [ainvr2/manage-acc-services.htm]
- Archive to NAS: Server panel > Network Storage Management > Enabled > Protocol CIFS (//host/path) or NFS (host:/path) > Network Path > Username/Password > Apply. [ainvr2/enable-archive-video.htm]
- Storage panel: Virtual Disks (RAID mode, capacity, Ready/error; check consistency; check & repair filesystem needs Unity 8.7.2+/ACC 7.14.44+, ~20 min, services stop) and Physical Disks (Ready/error, eject → Offline before pull; rebuild after replacement; replace with same-capacity HDD). [ainvr2/manage-storage.htm]
- Network panel: per pane Automatic IP toggle or manual IP/Subnet/Gateway; Automatic DNS toggle or manual list; Docker IP Address Pools (+ Base/Size, restart). Two connections: corporate (discovery/Client) + camera network. [ainvr2/network.htm]
- Logs panel: Server Logs types (Analytics Service Exception/FCP/Logs, Exception, FCP, Server, WebEndpoint, LPR Add-on x3); System Logs (System, Boot, Web Server); Maximum Logs; Filter; Sync; copy/paste to text for Support. [ainvr2/logs.htm]
- Troubleshooting: NEVER re-image (voids warranty). Can't discover: check cable/LEDs; File Explorer Network; Client site AINVR2-PRM-<serial>; browse https://AINVR2-PRM-<serial>; arp -a vs MAC on serial tag. [ainvr2/troubleshooting.htm]
- HDD failure LEDs: green→orange→off = predicted fail; 4 short orange flashes/s = failed; green 3s/orange 3s/off 6s = rebuild aborted; slow green flash = rebuilding; off = safe to remove. Front diagnostic: steady blue healthy, blinking blue = ID mode, steady amber = fail-safe, blinking amber = fault (System Event Log); HDD/temperature/electrical/memory/PCIe amber indicators. PSU: blinking amber = PSU problem; blinking green = PSU firmware update. [ainvr2/d/led.htm]
- iDRAC reset without OS reboot: hold front system health/ID button 16 s until fans full speed. [ainvr2/d/reset-idrac.htm]
- Factory restore: monitor+keyboard (rear VGA/USB) > power-cycle > when BIOS progress bar nearly done hold "f" key > release at "reset latched -- waiting for release" > reconfigure from scratch + upgrade firmware. Use when admin password lost / firmware unusable. [ainvr2/restore-factory-default.htm]
- Enable analytics on appliance: Client > New Task > Site Setup > server > Server Analytics > tabs Classified Object Detection (VAC lic), Appearance Search (ENT), Face Mask Detection (ENT), Face Recognition (FACE), LPR (LPR), Visible Firearm Detection (VFD-1YR) > check cameras (capacity bars). Missing tab = license missing. Analytics upgrade kit required except LPR non-performance mode. LPR lanes: Site Setup > server > License Plate Recognition (button absent ⇒ activate LPR licenses) > lane > Name/Camera/License Plate Configuration/Pre-Post Event Record/Minimum Confidence/Enable/Max Image Analysis Rate 1-60. [ainvr2/enabling-analytics.htm]

# ENVR2X (streetlight-mount edge NVR, LTE/PoE) User Guide (bundle envr2x)
Base: https://docs.avigilon.com/bundle/envr2x/page/<path>
- Provision: power cord, RJ45 from workstation into any of 4 PoE ports. Discover in File Explorer as "ENVR2X-RGD-STREETLIGHT-MOUNT-4TB-<serial>" > open > cert warning > set administrator password (only user) > Dashboard. Browser must accept cookies. [envr2x/preparing-to-install-envr2x/accessing-management-interface-first-time.htm]
- First config: General > System > Language; Hostname (changing hostname may affect Cloudflare); Time > Time Zone + NTP. [envr2x/preparing-to-install-envr2x/configuring-first-time.htm]
- LTE remote access = Cloudflare ZTNA: Cloudflare account + Cloudflare One client on workstation + device profile/split tunnel to appliance IP + Gateway network policies. Create tunnel: Zero Trust > Networks > Connectors > Create a tunnel > Cloudflared > name > Save > copy token > CIDR tab = Appliance IP Address (private RFC1918; avoid 172.16.0.x/24 if passthrough, 172.17/16, 172.18/16, 10.0.0.x/24). On ENVR2X: General > Optional Packages > enable Cloudflared > Cloudflared page in sidebar > Appliance IP Address + Application IP Address > paste token in Secrets > Apply > optional Disable Auto Update Off, Tunnel Protocol HTTP/2 (TCP, avoids carrier throttling; quic/auto UDP if unstable; restart app after change) > Restart > verify tunnel Healthy in Cloudflare > LTE-only: disconnect corporate LAN, General > Reboot (PWR orange → green) > reach Management Interface / add to site via Appliance IP. [envr2x/preparing-to-install-envr2x/connecting-to-cloudflare-ztna.htm]
- Camera Network Passthrough (cameras needing internet e.g. L6D): Network page > Manage Camera Network Passthrough toggle > auto restart > local DHCP on PoE ports 172.16.0.x/24 (change in Camera Network card > General; gateway 172.16.0.1 also reaches Management Interface). Camera IPs: Client > Site Setup > Connect/Disconnect Devices > Discovery pane. [envr2x/enabling-camera-network-passthrough.htm]
- Network panel: Automatic IP / manual; Automatic DNS; Docker IP Addresses (+ Base/Size, 8.6+, restart). [envr2x/management-interface/managing-network-settings.htm]
- Logs: General > Support pane > download all Device Logs (Server + System). Server logs per service under Unity Server menu (Daemon: Service/Exception/Metrics; Web Endpoint; API Gateway; Cloud Bridge; Core; Device Management; Local Update); System Logs under Settings > Logs. [envr2x/management-interface/providing-logs.htm]
- LEDs (under cover/access panel): PWR steady green healthy, steady orange restarting, blinking orange factory restore; SSD steady red = storage error. Link LEDs: right green 1000 Mbps, left orange 100 Mbps, both = 10 Mbps. [envr2x/led-indicators.htm]
- Soft reset: open access panel > pin-press Reset 1 s (PWR orange → green). Factory restore: hold Reset ~20 s until PWR blinks orange > release > reboot; wipes config/video AND Cloudflare config (re-provision on site). Remote reset/restore possible via Motorola Solutions Support. Never re-image. [envr2x/resetting.htm]

# Multi-Server Site Guide 8.8 (bundle unity-video-multi-server-site-8-8)
Base: https://docs.avigilon.com/bundle/unity-video-multi-server-site-8-8/page/<path>
- Don't cluster over WAN/VPN/wireless (latency), across broadcast domains, or for <50 cameras. [system-management/multi-server-do-not.htm]
- Mandatory: Enterprise license (not in grace period); same NTP; identical software version; disconnect from Unity Cloud (UCS) before merge; disable AD Sync on joining server; LAN <5 ms; same switch ideally; all cameras reachable by all servers (failover). [system-management/multi-server-site-sys-reqs.htm]
- Network rules: ONE default gateway per server (management NIC only; camera NIC gateway blank); one IP per NIC; NICs not routable to each other; no Windows static routes (route at switch); 10G NICs Active/Standby, never LACP-aggregated; dedicated NIC for iSCSI/NAS; NIC profile Private/Domain (Public firewall blocks services); physical hardware preferred, VMs need dedicated physical NICs. [system-management/multi-server-site-net-config.htm]
- Ports (all TCP+UDP between servers in multi-server; site families only TCP child→parent): 38880 TCP site mgmt/merge/login/upgrades/map sync; 38881 TCP HTTPS video forwarding proxy + secure API; 38882 UDP real-time replication (multi-server only); 38883 UDP discovery multicast 239.255.255.238 (multi-server only); 389/636 UDP AD to every DC; 38980 TCP Postgres DB replication (multi-server only); 38981 TCP DB; 38982 TCP gossip clustering; 38983 TCP MQTT clustering. [system-management/multi-server-site-port-config.htm]
- Ops: unique hostnames resolvable (DNS/hosts); backups; ipconfig /all + route print records; UPS; connect AI appliance to NVR BEFORE merging NVR; AV exclusions; finish organizing site before activating license (else reactivate every add). [system-management/multi-server-site-operational-practices.htm]
- AD: log in with LOCAL admin (only account on joining server); joining server on same domain; AD enabled on site. Hardened-OS appliance joining Windows site: Site Setup > Users and Groups > External Directory > Active Directory > Edit > clear "Use Avigilon Unity service account" + "Enable nested groups" > explicit username/password > OK. [system-management/multi-server-site-ad-requirements.htm]
- Merge: New Task > Site Setup > Site Management > drag server onto target site > Yes. Joining server's license goes inactive → Reactivate site license immediately; reconnect UCS after merge. Merge rules: unique settings added; identical → site version kept; name conflicts renamed "<setting> (servername)"; rules/alarms merged (duplicate Default Notify Rule one disabled); site org overrides; groups merged (site group wins, users added); duplicate usernames share settings incl. password. Must disconnect from site before changing hostname/IP, reinstalling/upgrading OS, or replacing hardware. [system-management/multi-server-merge-server.htm]
- Failover: Site Setup > site > Connect/Disconnect Devices > device > Edit… > Change on server > Connection Type Primary/Secondary/Tertiary > License Priority 1 (highest)–5 > OK. Server-based only; needs failover license per camera; enable mic/speaker on Secondary/Tertiary for audio. [system-management/failover-connections.htm]
- Troubleshoot: merge fails / DB sync timeout → multiple gateways (route print: only one 0.0.0.0 entry); server offline in Site Health but connected → internal static routes/multi-homing; latency/packet loss → 10G aggregation → Active/Standby. [system-management/multi-server-troubleshoot.htm]
- Custom CA certs (Windows): certlm.msc > request via AD Enrollment Policy > General tab Friendly Name exactly AccServerCert or UnityServerCert (case-sensitive) > Private Key tab > exportable > Enroll. Import root CA into Trusted Root on every client+server; restart "Avigilon Unity Orchestrator Service". Then Client > ⋮ > Client Settings > Security > Require trusted server certificates; and Site Setup > site > Security > Require trusted server certificates. [system-management/multi-server-custom-certs.htm]
- Restrict login to parent site: parent Setup > General > "Restrict login to only Global and Unranked users" (local ranked users blocked; LDAP/ACM/Cloud users never blocked). [system-management/multi-server-restrict-login-parent.htm]
- Remove server: copy license keys first; Site Setup > Site Management > server > Disconnect from Site… > Yes (restarts as standalone; may be unlicensed); reactivate remaining site license; clients: close Client > Remove All Known Sites. Dead server: from another server Site Management > offline server > Disconnect from Site… (prevents ghost entries); disconnect BEFORE reformat/OS upgrade; recovery: rejoin clean server first, then Restore backup > Custom Settings > Device Connections + Views. [system-management/multi-server-remove-server.htm]

# IPv6 Configuration and Migration 8.8 (bundle unity-video-ipv6-migration-8-8)
Base: https://docs.avigilon.com/bundle/unity-video-ipv6-migration-8-8/page/<path>
- Prereqs: NTP, DHCPv6, ICMPv6 MUST be allowed (scope ID resolution for fe80:: link-local). Unsupported: temporary/privacy addresses (RFC 4941), ::ffff: IPv4-mapped, H3 cameras/firmware ≤2022, native drivers (ONVIF only), Linux Unity Server, hardened appliances, Web Endpoint, ACS, mobile. Wait ≥10 min (up to hours) after enabling IPv6 before disabling IPv4 (no UI indicator). Camera factory reset: choose "Keep network settings". [customizing/ipv6-prerequisites.htm]
- Windows host: admin cmd: `netsh interface ipv6 set global randomizeidentifiers=disabled` and `netsh interface ipv6 set privacy state=disabled` > reboot. [customizing/ipv6-host-os-preparation.htm]
- Enable on server: Admin Tool > Settings tab > Network > Enable IPv6 > OK > Yes restart. [customizing/ipv6-enabling.htm]
- Camera (H6A WebUI): Setup > Network > IPv6 Settings > Enable toggle > Accept Router Advertisements > DHCPv6 (Auto default) > static addresses; or Client > Site Setup > camera > Network > Enable IPv6 Settings (non-Avigilon ONVIF read-only). [customizing/ipv6-camera-prep.htm]
- Discovery priority: Hostname > IPv6 > IPv4; existing connections never auto-switch protocol — disconnect and reconnect with IPv6 address. [customizing/ipv6-connection-priority.htm]
- Verify: IPv6 Address column in Connect/Disconnect Devices; restart server → link-local cameras reconnect; restart "Avigilon Analytics Service" after IPv6-only migration. Partition recovery: re-enable IPv4 at switch, verify unique IPv6, restart servers. Canceled Range Search keeps discovering up to 5 min. [customizing/ipv6-troubleshooting.htm]
