# ACC and ACM Integration Guide (bundle acc-acm-integration) — Alarm Gateway + VidProxy (NOT unification; unification = acc-acm-unification bundle)
Base: https://docs.avigilon.com/bundle/acc-acm-integration/page/<path>

- Two components: Alarm Gateway (Windows service + Configuration Tool mapping ACM device events → ACC External Software Event alarms; acknowledge/purge sync both ways; Purge in ACC = Clear in ACM) and VidProxy (ACM pulls live/recorded ACC video; must be installed ON the ACC server). Installer AvigilonAcmIntegration-6.14.20.2.exe (deselect a component: "Entire feature will be unavailable"). Requires ACC 7+ Standard/Enterprise, ACM 6.16+. [acm/requirements.htm]
- ACC side (Alarm Gateway): dedicated ACC integration user (no permissions needed but MUST be recipient of every mapped alarm; restart gateway service after password change). Alarms: Site Setup > Alarms > Add > External Software Event > linked cameras + Pre-Alarm/Recording Duration > recipients incl. integration user > optional DO on acknowledge > name/priority > Enable alarm. [acm/alarm-gateway/configuring-acc/add-acc-alarms.htm]
- ACM side: integration user delegated Identities Listing, Get Alarm Types For Device, Doors/Panels/Subpanels/Inputs/Outputs Listing, Alarm Monitor Acknowledge, Alarm Monitor Clear. Alarm event types: Settings > Event Types > select > Alarm checkbox (or Add New Event Type); assign events: Physical Access > Events > event > Event Type. [acm/alarm-gateway/configuring-acm/configure-acm-alarms.htm]
- Alarm Gateway Configuration Tool (Start > Avigilon > ACM to ACC Alarm Gateway): Configure Connections > Add ACC server IP/user/pass; ACM Server IP, ACM Server Port 443, ACM Service Port 6050 (required), ACM user/pass > Test Connection > Done. Map: pick ACC alarm > ACM Device Type / Parent Panel / Subpanel / Device / Alarm / Identities (Select All Identities incl. future) > ">>" > Save and Apply. Backup: C:\Program Files\Avigilon\ACM to ACC Alarm Gateway\AlarmConfig.xml. [acm/alarm-gateway/configuring-alarms/server-settings.htm]
- Alarm Gateway troubleshooting: can't select ACM alarm → ACM unreachable, Test Connection. No ACC alarms listed → ACC server running/same network, integration user added to alarms, creds. Mapped alarms "Unknown" in red → ACC server rebooted/offline; reopen Configure Connections (status Ready), Save and Apply; else restart "CrossFire Framework" and "CrossFire Server Component Framework" services. Not synchronized → services.msc restart "ACM to ACC Alarm Gateway Service". Alarms not in ACC Client → Std/Ent license; disable "Auto-acknowledge alarm immediately after it activates"; ports 443/6050; only ONE ACC SDK version installed; no Unicode in ACC creds; sites not merged after mapping; AlarmConfig.xml on same machine; restart service; reinstall integration + SDK. [acm/alarm-gateway/troubleshooting/alarms.htm]
- VidProxy: ACC integration user needs View Live Images, Use PTZ controls, Lock PTZ controls, View Recorded Video. ACM: Settings > External Systems > Avigilon tab > Add New Avigilon Server: Name, Address (ACC server IP), Port 8080 (VidProxy config file port must be 8080; restart VidProxy service; re-set after upgrade), Remote Username/Password (ACC), Local Username/Password (ACM), Installed > Save → status "Backend Up". Cameras to doors: Physical Access > door > Cameras tab > Camera Type = external system > move cameras to Members > Save; verify Door Hardware > Door Position/REX input > Cameras field. [acm/vidproxy/configuring-acc/add-acc-servers.htm]
- VidProxy troubleshooting: integration stops → "Avigilon VidProxy" Windows service started (port conflict if won't start), ACC running, firewall. No video in popup → browser blocks mixed content: click security icon > Load unsafe scripts, or allow insecure content in browser. [acm/vidproxy/troubleshooting/no-images.htm]
