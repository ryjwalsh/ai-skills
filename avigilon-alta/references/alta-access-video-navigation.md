## Alta Access web app (bundle alta-access-admin)
- Sign in: alta.avigilon.com/signin > select org/region; MFA prompted on first login; passwords ≥15 chars w/ upper/lower/number; SSO via IdP (namespace error = multiple IdPs, ask admin for namespace, e.g. org:company). Unified Alta Video + Alta Access orgs use the Alta Access password; app switcher doesn't work in Incognito. Legacy URLs: access.alta.avigilon.com/o/<orgId>/... (orgID after /o/). [alta-access/sign-in.htm]
- Top nav: Home (Dashboards: Activity / Alarms / Entry / Device / custom widgets, Maps, Cameras) · Users (users, access groups, roles, schedules, custom fields) · Sites (sites, buildings, zones, entries, entry states, entry schedules, lockdown plans, anti-passback) · Devices (ACUs, Readers, Wireless locks & gateways, Video readers, Video intercom readers, Intercom Touch, Device update management) · Reports (alarms, activity logs, portal audit, muster, occupancy) · Apps (marketplace) · Config (Alerts, Alarms, Badge design, Intercom user directory, Rules, Event definitions) · Admin (Account, Quick start, Licenses). - Quick start (site + ACUs + readers in one page): Admin > Quick start > Site name/language > Next > controllers: name + Controller type (First generation Red Board OP-AS-01 / Single Door Controller / Core series ACU) + EXPANSION BOARDS (Openpath 4-Port, 8-Port, 16-Port Elevator, Avigilon 32-Input; Core ACU max 2 boards) > readers count/names > Confirm & submit. Not for Access Control Core + Mercury (add one at a time). [alta-access/administration/quick-start.htm]
- Network: DHCP Ethernet; outbound TCP 443 (all controllers/readers, dynamic cloud IPs), UDP 123 pool.ntp.org, UDP 53 if external DNS, UDP 3478 TURN + UDP 50000-60000 WebRTC (Video Reader Pro / Video Intercom Reader Pro / Intercom Touch); Alta Video cameras & Intercom Touch: TCP/UDP 443 to *.aware.avasecurity.com, alta.avigilon.com, *.dmp.alta.avigilon.com, *.motorolasolutions.com, *.calipsa.io, *.geo-turn.aware.avasecurity.com, upgrades.video.alta.avigilon.com, *.storage.aware.avasecurity.com; Smart Path UDP 32768-65535 → 1024-65535. No inbound forwarding; no TLS inspection; Fortinet AV blocks AWS by default (allowlist). Lockdown plans spanning controllers need two-way TCP 443 between controllers, no NAT, DHCP reservations/static. SDC Wi‑Fi unlock needs inbound TCP 443 on LAN. Put PoE readers' Ethernet on a DMZ. Reader upload bandwidth 1/2/8 Mb (low/med/high). [alta-access/network-requirements-devices.htm]

- Device updates: Devices > Device update management > "Important update - Action required" (2-hour window, manual). Reader/board firmware ~5 min each (auto retry ×3; readers blink red). ## Alta Access hardware (bundles op-cr-acc-install, op-cr-sdc-install, sys-*-install)
- Access Control Core (OP-CR-ACC) status LED: solid green provisioned OK; solid cyan booting; solid yellow restoring software (first power-on / hard reset); blinking yellow updating (<24 h online; >3.5 h stuck → Support before power cycle); solid blue unprovisioned/ready; blinking purple ready for mobile app; solid purple connected to app; blinking red no internet or config saving (should clear in ~5 s); solid red error → Devices dashboard. SDC same but solid WHITE = normal; SDC port LEDs: readers solid normal/blinking error; sensors solid active/blinking EOL shorted or cut; relays solid energized/blinking fault. 8-Port Expansion Board: solid green OK, solid red comm error (power cycle, reseat USB, Home > Device > REMOTE DIAGNOSTICS > Restart device communicator), blinking red firmware update; Board ID LED = EXPANSION BOARD NUMBER. [hardware/op-cr-acc/led-indicators.htm]
- Provision (recommended): Alta Access mobile app ≥2.4.0 (iOS 16+/Android 5+) > + icon > fill > Create and provision (creates expansion boards; ACU registers under Devices > ACUs). Mercury boards must be added via web. Network settings via app: press Admin button to connect > Network settings > Configure network manually (static IP/DNS; recommend DHCP reservation). Test Internet Connection pings api.openpath.com/health. [hardware/op-cr-acc/creating-and-provisioning-mobile-app.htm]
- ACU/SDC offline: soft reset (remove power+battery 30 s; reboot router 30 s) → causes: ISP/power (use UPS), IP assignment (expand subnet/static), firewall (443, 123, 53), bad patch cable/switch (connect direct to modem), relay power draw. Hard reset (installers only, Support-directed; wipes + reprovision): power off > hold Admin button > reconnect power > hold 15 s until LED yellow > release > wait for blue > reprovision (SDC: same slot/name). [hardware/reset-acu.htm]
- Faulty reader/port: measure 12 V DC at reader port; check wiring; power down; swap terminal blocks with a working reader; if reader now works → port faulty, else reader/wiring. [hardware/issues-readers.htm]
- Reader wiring (RS-485): prefer shielded CAT6A > shielded Cat6 > shielded RS-485 18-24 AWG > … ; one pair GND+VIN, one pair +B/-A; max 300 ft CAT6 (500 ft with doubled power pairs); drain wire to ACU GND one end only; remove power before wiring. [hardware/wiring-readers.htm]
- SDC relays: voltage switch 12V/24V (wet: NO+GND fail-secure, NC+GND fail-safe) or DRY (external supply via NO/NC + C); 24 V locks need PoE or 24 V PSU; backup PSU 12 V @2.2 A or 24 V @1.1 A; don't remove SD card. [hardware/op-cr-sdc/voltage-switches.htm]
- EOL supervision (4/8-Port boards, single or double 1k): Devices > ACUs > ACU > Ports > Cable > None / Cut Line Detect / Line Shorted Detect / Both; alerts "Input EOL State Changed"; rules on *-end-of-line supervision state changed. [hardware/end-of-line-supervision.htm]
- Mercury with Access Control Core: power + LAN > S1 DIP ON (web login) > browse 192.168.0.251 admin/password > Network > Use Static IP configuration + DNS (same subnet/LAN segment as ACU) > Host Comm > Communication Address 2, Port 3001, Data Security TLS Required, Allow All > Apply Settings > Log Out > S1 OFF. Then Alta Access add ACU with Mercury board IP/port/TLS. Config changes restart panel services briefly. [hardware/op-cr-acc/mercury/controllers-subpanels.htm]
